01

Six rules every screen follows

If a design choice breaks one of these, the rule wins. They come straight from the decision report: a DLP tool that nags gets uninstalled, and a security extension that isn't trusted is worthless.

1. Silent by default

No UI until a secret or risky package shows up. We never show a "you're protected" banner on every page load. The toolbar icon is the only thing that's always visible.

2. Warn and redact, never block

The default fixes the problem and keeps the user moving. Sending the original takes a deliberate press-and-hold, never an accidental click.

3. Focus stays with the user

Our UI never takes focus from the chat box. Enter and Esc keep working exactly as the user expects.

4. Show what we saw, not what we know

We describe secrets by type ("Stripe key") and never show their values in our own UI, logs or badges. Values only reappear inside the user's own conversation.

5. Explain in place

Every verdict can explain itself with one hover or focus: why it was flagged, what the AI saw, and how to allow it. There are no dead ends and no settings maze.

6. Motion is information

The hatch tape means "protected" everywhere. Anything that moves is either confirming an action or showing a change of state. Nothing moves just to look busy.

1

Paste is caught before it lands. A capture-phase paste listener runs detection in under 5 ms. The real value never reaches the page's editor.

2

Tape stamps in, the chip explains. Each secret becomes a PG_SECRET_n pill (stamped in 260 ms, 50 ms stagger), and the chip rises from the composer in 180 ms. Esc undoes it instantly.

3

The AI only sees placeholders. Enter sends. The values stay in a session-only vault in memory and are never written to disk.

4

The answer is restored for you. The tape peels off (320 ms) to show the real value. Hover it to see what the AI actually saw.

5

Install commands are checked. Package names in code blocks get a verdict chip. Verdicts in this demo are samples; the extension queries the npm and PyPI registries.

The trust model, drawn

Coral packets are real secrets and never cross the dotted device boundary. Yellow packets are placeholders, and they are the only thing the AI site receives. We keep this diagram on the store listing and the "What we see" page.

Permission prompt, designed

The public build asks only for AI chat domains and the npm/PyPI registries. The install warning names four sites instead of "all websites". The team build adds webNavigation and management, but it's force-installed, so users never see a scary prompt.

"What we see" page

This is a paper-surface table with the columns Data, Where it lives, Who can see it and How long. Every row links to the file in the open-source repo that handles it.

No remote anything

No remote code, no remote fonts and no analytics inside host pages. The in-page UI uses the system font stack, so there are zero network requests on AI sites.

05

Motion system

Based on Emil Kowalski's design-engineering rules: how often something is seen decides whether it animates, exits are faster than entrances, only transform, opacity, clip-path and filter are animated, and we use custom curves because the built-in easings are too weak.

Rules we check in review

  • No transition: all. Name the properties.
  • Never animate from scale(0). Start at .94–.98 with opacity.
  • Interruptible UI (chip, badge) uses transitions, not keyframes.
  • Tooltips and popovers scale from their trigger, not from center.
  • Hover effects only under (hover: hover) and (pointer: fine).
  • Loops pause off-screen and when document.hidden.
  • Reduced motion: keep opacity and blur, drop movement.

06

Accessibility

The in-page UI lives inside someone else's accessibility tree, so it has to be announced without interrupting and reachable without stealing focus.

Announce, don't interrupt

  • Chip: role=status, polite. "2 secrets replaced with placeholders."
  • Verdicts are announced once per answer, not once per badge.
  • Exposed sends use assertive. That's the only interruption we ever make.

Keyboard map

  • Enter send taped · Esc undo tape
  • AltShiftP move focus to the chip; Esc returns it to the composer
  • Hold-to-send also works with a held Space.

Visual

  • Marker on ink is 12.9:1, paper-ink on paper is 15:1, alert on ink is 5.6:1.
  • State is never conveyed by color alone: tape pattern, icons and text too.
  • Targets are ≥ 24px (2.5.8) and ≥ 44px on the welcome and uninstall pages.
  • Forced-colors mode gets outlines on pills.

07

Engineering rules for the UI

Industry practice for running UI inside hostile pages, plus the budgets that keep us invisible when nothing is wrong.

Isolation

  • One host element per page, with a closed shadow root and :host { all: initial }. Host CSS can't reach in and ours can't leak out.
  • Render in the top layer with popover="manual", so there are no z-index wars with the site's own modals.
  • Build DOM with textContent and createElement only. There's a lint rule against innerHTML.
  • MAIN-world script: one wrapped function, clipboard.writeText, under 40 lines, audited.
  • Per-site adapters sit behind one interface: composer(), answers(), send(). They get daily Playwright checks.

Budgets

Content script (gzip)≤ 25 KB
Detect 10 KB paste≤ 5 ms p95
Idle cost on AI page0 timers, 1 observer
Restore per mutation≤ 2 ms, 50ms debounce
Package verdict≤ 600 ms, cached 24h
Popup first paint≤ 100 ms
Network on AI pages0 requests

Theming

  • Extension pages follow prefers-color-scheme, with ink as the default.
  • In-page UI is always paper, so it doesn't depend on the host theme and never mismatches.
  • Fonts: extension pages bundle Bricolage, Rubik and JetBrains Mono locally. Host pages use the system stack.

i18n and layout

  • All strings go through chrome.i18n; UI tolerates +40% string length.
  • Logical properties only (inset-inline, margin-inline), so RTL works for free.
  • Numbers use Intl.NumberFormat, dates use Intl.RelativeTimeFormat ("4 days ago").
